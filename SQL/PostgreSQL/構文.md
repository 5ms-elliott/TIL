## キャスト
SQL標準形式：　
```SELECT CAST(12345 AS text);```  
PostgreSQL独自形式：
```SELECT 12345::text;```

## 既存のテーブルから構造のみをコピーして一時テーブルを作成 
```CREATE TEMP TABLE tmp_table1 ON COMMIT DELETE ROWS AS select * from table2 limit 0;```   
※ limit 0 ・・・元のテーブルから０行レコードをコピーする ＝ レコードはコピーしない  
※ COMMIT DELETE ROWS　・・・現在のトランザクションをコミットする際に、一時テーブルの全行は削除される 

## VACUUMコマンド 
データベースのパフォーマンスを維持するために重要なコマンドです。  
データの更新や削除が行われると、不要なデータ（デッドタプル）が残ります。これらを削除し、ディスクスペースを再利用可能にすることで、データベースの効率を向上させます。 
 
### 基本的な使い方 
```VACUUM table_name;``` 
### 主なオプション 
```VACUUM VERBOSE```  
実行中の詳細な情報を表示します。デバッグやパフォーマンスチューニングに役立ちます。  
```VACUUM FULL```  
テーブルを再構築し、不要なスペースをOSに返します。ただし、テーブルをロックするため、長時間の実行は避けるべきです。  
```VACUUM ANALYZE```   
VACUUMの後に統計情報を更新し、クエリプランナーが効率的な実行計画を作成できるようにします。  
### 自動化機能: AUTOVACUUM 
PostgreSQLにはAUTOVACUUM機能があり、データベースが自動的にVACUUMとANALYZEを実行します。  
これにより、手動での管理作業が軽減されます。ただし、データベースの特性に応じて適切に設定を調整する必要があります。 

*注意点  
VACUUM FULLは通常の運用では推奨されませんが、大量のデータ削除後など特定のケースで有用です。  
VACUUMの実行中はI/Oトラフィックが増加し、他のセッションのパフォーマンスに影響を与える可能性があります。 

## マテリアライズドビュー 
### ビューとの違い  
ビュー　・・・クエリに名前を付けて保存したもの。クエリの定義のみでデータは保持していない。  
  →参照するたびにSQLが実行される為、パフォーマンスに影響する。 
マテリアライズドビュー　・・・クエリの結果をディスク上に物理的に保存するデータべースオブジェクト。 
### 使用例 
ダッシュボードやレポート用の集計クエリ（毎回重い集計をしたくない場合）  
バッチ処理の結果を高速に参照したい場合  
データウェアハウスでの分析クエリの高速化 
### 基本的な使い方 
作成　　(作成と同時に、クエリが実行されて結果が保存される) 
```
CREATE MATERIALIZED VIEW daily_sales_summary AS 
SELECT 
    DATE(ordered_at) AS order_date, 
    SUM(amount)      AS total_amount, 
    COUNT(*)         AS order_count 
FROM orders 
GROUP BY DATE(ordered_at); 
```
(データを保存せずに定義だけ作りたい場合) 
```
CREATE MATERIALIZED VIEW daily_sales_summary 
WITH NO DATA AS 
SELECT 
    DATE(ordered_at) AS order_date, 
    SUM(amount)      AS total_amount, 
    COUNT(*)         AS order_count 
FROM orders 
GROUP BY DATE(ordered_at); 
```
リフレッシュ  
```REFRESH MATERIALIZED VIEW daily_sales_summary; ```  
削除  
```DROP MATERIALIZED VIEW daily_sales_summary; ```
