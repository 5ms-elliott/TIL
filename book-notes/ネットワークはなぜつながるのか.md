# TCP/IP、LAN、光ファイバの基礎知識

## 1. webブラウザがメッセージを作る
ブラウザにURLを入力すると・・・
* ブラウザがURLを解読
  * HTTPプロコトルでwebサーバーにアクセスする場合  
    例) http://user:password@www.glasscom.com:80/dir/file.htm  
        http://ユーザー名:パスワード@webサーバーのドメイン名:ポート番号/ファイルのパス名  
          省略可　(⚪︎)　　　(⚪︎)　　　　　　　　　　　　　　　　　(⚪︎)　　　(⚪︎)  
      ※ファイル名が省略されていた場合は、index.htmlやdefault.htmのファイルにアクセスするように設定しているサーバーが大半。  

* HTTPのリクエスト・メッセージを作る

* リクエストを送ると、レスポンスが返ってくる
  ステータスの実行結果を表すステータスコードを含む (404 NotFound等)
  | コード値 | 説明 |
  |:--|:--|
  |1xx|処理の経過状況などを通知する。|
  |2xx|正常終了。|
  |3xx|何らかの別のアクションが必要であることを表す。|
  |4xx|クライアント側のエラー|
  |5xx|サーバー側のエラー|

  リクエスト・メッセージに書くURLは１つだけ。複数のファイルを読み出すときは、別々にリクエスト・メッセージをWebサーバーに送る。

* webサーバーのIPアドレスをDNSサーバに問い合わせる  
    DNS ...Domain Name System  ドメイン名が分かればIPアドレスが分かる。逆も然り。という仕組みのこと。  
  　ドメイン名からIPアドレスを調べるとき、ブラウザはSocketライブラリのリゾルバを利用する。  

* 正解中のDNSサーバーが連携する  
    ドメインの階層  
    例) www.lab.glasscom.com  --- 組織流儀で書くと ---> com事業部 glasscom部 lab課の www  

* プロトコル・スタック(OS内にある)にメッセージ送信を依頼する  
  【データの送受信動作】
  * ソケットを作る
  * サーバー側のソケットにパイプを繋ぐ
      IPアドレスで識別できるのはどのコンピュータか、まで。どのソケットか識別するのに必要なのはポート番号。
  * データを送受信する
  * パイプを外してソケットを抹消する

## 2. TCP/IPのデータを電気信号にして送る
* ソケットを作成する  
  【OSに組み込まれたネットワーク制御用ソフトウェア(プロトコル・スタック)の内部構成】  
  * ブラウザやメールなどの通常のアプリケーションがデータを送受信する場合は**TCP**  
    DNSサーバーへの問い合わせなどで短い制御用のデータを送受信する場合は**UDP**
  * IP ・・・パケットを運ぶ、経路を決める  
      IPの中にはICMP(パケットを運ぶ際に発生するエラーを通知する。制御用のメッセージを通知する)とARP(IPアドレスに対応するイーサネットのMSCアドレスを調べる)がある
  * OS下にあるLANドライバ　・・・LANアダプタのハードウェアをコントロールする
  * LANアダプタのROMには、全世界で重複しないよう一元管理されたMACアドレスが製造時に書き込まれている
  * プロトコル・スタックはソケットに記録された制御情報を参照しながら動く。
  * ソケットを作るとき、ソケット１つ分のメモリー領域を確保して、そこに初期状態であることを記録する。
* サーバーに接続する
  * 通信相手との間で制御情報をやり取りして、ソケットに必要な情報を記録し、データ送受信可能な状態にする 
   データ送受信動作を実行するときは、送受信するデータを一時的に格納するメモリー領域(バッファ・メモリー)が必要。
  * 通信動作に用いる制御情報は２種類
    * ヘッダーに書き込まれる情報
    * ソケット（プロコトル・スタックのメモリー領域）に記録される情報
  * TCPヘッダーの送信元と宛先のポート番号で接続するソケットを特定する
* データを送受信する  
　IPパケットを電気や光の信号に変換して送信

  * プロトコル・スタックにHTTPリクエスト・メッセージを渡す  
    MTU ・・・１つのパケットで運ぶことができるデジタル・データの最大長のこと。イーサネットでは、通常1500バイト。  
    MSS ・・・ヘッダーを除いて、1つのパケットで運べるTCPのデータの最大長
  * パケットが届いたことをACK番号を使って確認  
    データが長い場合に分割して送信するが、その際に何バイト目まで受信したかというACK番号を返す
  * パケット平均往復時間でACK番号の待ち時間を調整  
    ACK番号が返るのを待つ時間　＝　タイムアウト値
  * ウインドウ制御方式でACK番号を効率よく管理　・・・ACK番号が返ってくるのを待つ間に次の送信を行うので無駄がない
  * HTTPレスポンス・メッセージを受信
* サーバーから切断してソケットを抹消  
  データの送受信が終わってから数分程度待ってからソケットを抹消するのが一般的。
